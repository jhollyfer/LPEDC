Módulo 13 · Busca e ordenação

Busca sequencial e binária, os três métodos O(n²) e os dois O(n log n), com qsort e bsearch. Em cada algoritmo você conta comparações e trocas. Depende de vetores, ponteiros, recursão, malloc, structs e do Big-O do módulo 10; o 14 leva a busca binária para a árvore.

O que você vai aprender

  • busca sequencial: custo O(n) e sentinela
  • busca binária: O(log n) em vetor ordenado, invariantes e erros de um
  • bubble, selection e insertion sort, O(n²)
  • merge sort e quick sort, O(n log n) por dividir e conquistar
  • estabilidade, ordenação in-place e como escolher o algoritmo
  • qsort e bsearch, com funções de comparação corretas

Antes de começar

Nos diagramas, cada linha de gavetas é um momento do algoritmo: amarela é a gaveta comparada (ou o menor achado), roxa é a posição ou o pivô da vez, verde já está no lugar e cinza foi descartada. Faça o Passo a passo no papel antes de conferir a tabela.

O contador de comparações não faz parte do algoritmo: mede o custo, que não muda de máquina para máquina. Compile com as flags de estudo: o AddressSanitizer e o UBSan param o programa nos erros de índice e de overflow.

Desafios do módulo

Problemas para fechar o módulo, misturando os assuntos. Escreva em C e compile com o gcc e as flags de estudo.

1. Quantas voltas no pior caso? Escreva a busca binária com um contador de voltas do laço, devolvido por um ponteiro int *voltas. Num vetor criado com malloc e preenchido só com pares (v[i] = 2 * i), busque todos os ímpares de -1 a 2n - 1 (todas essas buscas falham) e mostre o maior número de voltas que alguma delas deu. Rode com n = 5000 e com n = 5000000.

Resposta
n = 5000: no máximo 13 voltas
n = 5000000: no máximo 23 voltas

O intervalo cai pela metade a cada volta: o máximo é ⌊log₂ n⌋ + 1. Para 5.000, 2¹² = 4096 ≤ 5000 < 8192 = 2¹³, então 13 voltas; para 5 milhões, 2²² ≤ 5.000.000 < 2²³, então 23. Mil vezes mais dados, só 10 voltas a mais. Caminho: ini = 0, fim = n - 1, (*voltas)++ logo no começo do while (ini <= fim), e no main um laço for (int x = -1; x <= 2 * n - 1; x += 2) guardando o maior. Use meio = ini + (fim - ini) / 2; com 5 milhões, a soma ini + fim ainda cabe em int, mas o hábito evita o estouro.

2. O par que soma. Dado um vetor ordenado 3 8 11 15 19 24 30 e um valor alvo = 34, ache dois elementos que somam o alvo em O(n), sem laço dentro de laço.

Resposta

Dois índices: i = 0 no começo e j = n - 1 no fim. Se v[i] + v[j] é menor que o alvo, i++; se é maior, j--; se é igual, achou. Para 34: 3 + 30 = 33 (i++), 8 + 30 = 38 (j--), 8 + 24 = 32 (i++), 11 + 24 = 35 (j--), 11 + 19 = 30 (i++), 15 + 19 = 34. Funciona porque o vetor está ordenado: cada passo descarta um elemento que não pode fazer parte de nenhum par.

3. Primeiro ordena, depois busca? Você tem um vetor desordenado de n = 100.000 elementos e precisa responder k buscas. Escreva um programa que calcule o custo dos dois planos em comparações: busca sequencial (uns n / 2 por busca) e ordenar (n · log₂ n) para depois fazer busca binária (log₂ n por busca). Calcule log₂ n arredondado para cima com um laço que dobra uma variável até passar de n. Mostre os dois custos para k = 1, 10, 34, 35, 1000 e, com um while, o primeiro k em que ordenar fica mais barato.

Resposta
log2(n) arredondado para cima: 17
Ordenar: 1700000 comparações
k =    1: sequencial     50000, ordenar + binária  1700017
k =   10: sequencial    500000, ordenar + binária  1700170
k =   34: sequencial   1700000, ordenar + binária  1700578
k =   35: sequencial   1750000, ordenar + binária  1700595  <- ordenar ganha
k = 1000: sequencial  50000000, ordenar + binária  1717000  <- ordenar ganha
Ordenar compensa a partir de 35 buscas

Igualando 50.000 k = 1.700.000 + 17 k, dá k ≈ 34: com mais de umas 34 buscas, ordenar compensa; com milhares, a diferença é enorme; com 1 ou 2, ordenar é desperdício. Use long nas contas: com k acima de uns 43 mil, k * 50000 passa do INT_MAX. O while (ordenar + k * lg >= k * (n / 2)) k++; acha o ponto de virada.

4. Ordenar 0, 1 e 2. Um vetor tem só os valores 0, 1 e 2 (por exemplo, 2 0 1 2 1 0 0 2 1). Ordene em uma passada, in-place, sem contar quantos há de cada.

Resposta

É a partição de três vias com pivô 1 (a "bandeira holandesa" de Dijkstra), com lt, i e gt. 0 vai para a frente (troca(v[lt], v[i]), lt++, i++), 2 vai para o fim (troca(v[i], v[gt]), gt--), 1 fica (i++). Resultado: 0 0 0 1 1 1 2 2 2, com n comparações.

5. Ordenar sem comparar. As notas de 3.000 candidatos são inteiros de 0 a 100. Ordene em O(n) usando um vetor contagem[101].

Resposta

Counting sort: um laço conta quantas vezes cada nota aparece (contagem[nota]++); outro laço percorre as notas de 0 a 100 e escreve cada uma contagem[nota] vezes. São O(n + 101) passos e nenhuma comparação entre elementos. Só funciona porque as chaves são inteiros num intervalo pequeno: o limite de O(n log n) vale para algoritmos que comparam.

6. O merge sort de baixo para cima. Escreva o merge sort sem recursão: intercale pedaços de tamanho 1, depois 2, 4, 8... até cobrir o vetor. Teste com as notas do assunto 0094, 52 18 33 7 41 26 60 12, e com um vetor de 7 elementos.

Resposta

Laço de fora: for (int b = 1; b < n; b *= 2). Laço de dentro: for (int p = 0; p + b < n; p += 2 * b) intercala [p, p + b) com [p + b, min(p + 2b, n)). O cuidado é o último pedaço, que pode ser menor (ou nem existir) quando n não é potência de 2. O resultado é 7 12 18 26 33 41 52 60.

7. Quick sort que não estoura a pilha. Mude o quick sort do assunto 0095 para fazer a recursão só no lado menor e tratar o maior com um while. Meça a maior profundidade de recursão num vetor já ordenado de 10.000 elementos, antes e depois.

Resposta

Antes, com o pivô no fim, a profundidade chega a 9.999. Depois, cada chamada recursiva recebe no máximo metade do pedaço atual, então a profundidade fica abaixo de log₂ 10.000 ≈ 14. As comparações continuam O(n²) nesse caso: o truque protege a pilha, não o tempo. Para o tempo, mude o pivô (meio ou mediana de três).

8. Quick sort híbrido. Faça o quick sort chamar o insertion sort quando o pedaço tiver menos de L elementos. Com o contador de comparações do A192, teste L = 1, 8, 16, 32 num vetor aleatório de 10.000.

Resposta

As comparações quase não mudam (às vezes até sobem um pouco), mas o tempo de relógio costuma cair, com o melhor valor em geral entre 8 e 32: o insertion não tem recursão nem chamadas, e pedaços pequenos cabem inteiros no cache. As bibliotecas de verdade fazem isso.

9. Mediana de duas listas. Duas lojas têm listas ordenadas de preços, com 5 e 6 itens: 12 30 45 60 88 e 9 25 41 50 70 95. Ache a mediana dos 11 preços sem criar um vetor novo.

Resposta

Faça a intercalação sem gravar: avance os dois índices como no merge, contando quantos elementos já "saíram", e pare no 6º (o do meio de 11). A sequência é 9, 12, 25, 30, 41, 45: a mediana é 45, com O(n) passos e O(1) de memória.

10. A compara que mente. Esta compara foi escrita para ordenar do maior para o menor: return *(const int *) a < *(const int *) b;. Ela compila. Escreva-a ao lado da versão certa, certa, e mostre o que cada uma devolve para os pares (3, 7), (7, 3) e (5, 5), marcando o par em que a errada devolve 0 com números diferentes. Depois ordene 52 18 33 7 41 26 60 12 com qsort e a certa.

Resposta
(3, 7): errada  1, certa  1
(7, 3): errada  0, certa -1  <- a errada diz que empatam
(5, 5): errada  0, certa  0
60 52 41 33 26 18 12 7

A errada devolve só 0 ou 1, nunca negativo: quando a > b, ela diz ao qsort que empatam. O contrato fica inconsistente (se a empata com b e b empata com c, a deveria empatar com c), e o resultado depende de como a biblioteca implementa o qsort: pode sair certo num computador e errado em outro. Por isso o teste olha a compara, não só o vetor ordenado. A certa é int x = *(const int *) a, y = *(const int *) b; return (x < y) - (x > y);, que devolve -1, 0 ou 1 sem risco de estouro.
