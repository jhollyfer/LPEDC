Módulo 07 · Memória dinâmica

Como pedir memória enquanto o programa roda, do tamanho exato, e devolvê-la ao acabar: heap, malloc, free, calloc, realloc, matrizes dinâmicas e os erros de memória. Depende dos ponteiros do módulo 06 e prepara listas, pilhas, filas, árvores e o módulo 08 (structs).

O que você vai aprender

  • as quatro regiões da memória: código, dados, heap e pilha, e quanto tempo vive cada coisa
  • malloc e free, sempre conferindo o NULL
  • calloc (memória zerada) e realloc, para o vetor crescer conforme os dados chegam
  • matrizes dinâmicas: bloco único com i * colunas + j ou vetor de ponteiros com m[i][j]
  • vazamento, ponteiro solto, free duplo e estouro, caçados com o AddressSanitizer e o valgrind
  • um programa com vetores que crescem e strings de tamanho exato, sem deixar nada para trás

Antes de começar

Domine ponteiros (módulo 06): &, *, NULL, a[i] == *(a + i), char * e **. Se int **m assusta, releia 0047 e 0049. Nos diagramas, o verde é o bloco do heap. Escreva cada exercício do zero, compile com as flags de estudo e leia o relatório do AddressSanitizer se algo estourar.

O gcc com as flags de estudo já compila com o AddressSanitizer, que avisa de vazamentos no fim. Para o assunto 0057, instale também o valgrind:

sudo pacman -S valgrind        # Arch Linux
sudo apt install valgrind      # Debian / Ubuntu

Rode qualquer arquivo com ele assim (sem AddressSanitizer):

gcc -g ~/LPEDC/material/A114.c -o ~/LPEDC/material/A114 && valgrind ~/LPEDC/material/A114

A regra do módulo: todo malloc tem um free, e nenhum ponteiro é usado depois dele.

Desafios do módulo

Resolva num arquivo seu, com as flags de estudo (e valgrind ./programa como segunda opinião). A versão final não pode gerar relatório de erro.

1. Apagar do caderno. No caderninho de fiado do texto do assunto 0058, escreva int remover(char **nomes, int *centavos, int *qtd, const char *nome), que apaga a linha do cliente e puxa as de baixo para cima. Teste removendo "Seu Jorge" e mostre o caderno.

Resposta

Ficam Dona Cida (17.20), Bia (20.00), Tonho (3.15) e Rosa (5.60), total R$ 45.95. O caminho: ache o índice i, faça free(nomes[i]) (o nome é um bloco), depois copie nomes[k] = nomes[k + 1] e centavos[k] = centavos[k + 1] para k de i até qtd - 2 e faça (*qtd)--. Um free só: os ponteiros puxados continuam apontando para os mesmos blocos.

2. A matriz de dois mallocs. Escreva int **criar_matriz(int l, int c) que usa só dois malloc: um bloco com os l * c inteiros e um vetor de l ponteiros com m[i] = bloco + i * c. Escreva também o liberar. Teste com uma matriz 3 x 4 preenchida com i * 4 + j e mostre m[2][3].

Resposta

m[2][3] vale 11. Para liberar: free(m[0]) (é o endereço do bloco de dados) e free(m). Dois malloc, dois free, dados contíguos e a notação m[i][j] preservada. Cuidado: free(m[1]) seria um erro, porque m[1] não veio de um malloc.

3. Matriz simétrica econômica. Numa tabela de distâncias entre 4 cidades, d[i][j] == d[j][i] e a diagonal é 0. Guarde só o triângulo de baixo (com a diagonal) num vetor alocado com malloc de n * (n + 1) / 2 posições, com o elemento (i, j), i >= j, em i * (i + 1) / 2 + j. Escreva int indice(int i, int j), que troca i e j quando i < j. Preencha o vetor com a tabela {{0, 12, 30, 25}, {12, 0, 18, 40}, {30, 18, 0, 22}, {25, 40, 22, 0}} (só o triângulo de baixo), imprima quantas posições o vetor tem, os índices de (3, 1) e de (1, 3) e, por fim, a tabela 4 x 4 inteira lida só do vetor, com %4d.

Resposta
posicoes: 10 (matriz cheia: 16)
(3,1) -> 7   (1,3) -> 7
   0  12  30  25
  12   0  18  40
  30  18   0  22
  25  40  22   0

Dica: preencha com dois laços, j indo só até i, gravando d[indice(i, j)] = dist[i][j]. Na hora de imprimir, os dois laços vão até n e o indice cuida da metade de cima: (1, 3) vira (3, 1), índice 3 * 4 / 2 + 1 = 7. Com n = 1000, a economia passa de 499 mil posições.

4. O gerente do heap. O heap tem dois blocos livres, de 120 e de 60 bytes (int livre[2] = {120, 60}), e chegam três pedidos: 30, 80 e 55. Escreva void simula(const char *nome, int best) que atende os pedidos na ordem, descontando do bloco escolhido, e imprime a cada pedido o bloco usado e o que sobrou nos dois (ou "falhou"). Com best == 0 é first fit (o primeiro bloco que serve, olhando o 0 antes); com best == 1 é best fit (o menor bloco que serve). Chame as duas.

Resposta
first fit:
  30: bloco 0, livres 90 e 60
  80: bloco 0, livres 10 e 60
  55: bloco 1, livres 10 e 5
best fit:
  30: bloco 1, livres 120 e 30
  80: bloco 0, livres 40 e 30
  55: falhou (livres 40 e 30)

Dica: para cada pedido, percorra os dois blocos guardando o índice escolhido (começando em -1); no first fit pare no primeiro que serve, no best fit troque a escolha quando achar um bloco que serve e é menor. Escolher "o mais justo" nem sempre é o melhor: deixa sobras pequenas demais. Os malloc reais usam variações de first fit com listas por tamanho.

5. Tem memória, mas não cabe. Simule um heap de 1000 bytes com um char heap[1000], todo preenchido com '.' (livre). Escreva int aloca(char dono, int tam), que procura tam posições livres seguidas a partir do começo, marca com a letra do dono e devolve o índice em que o bloco começa (ou -1), e void libera(char dono). Escreva também um relatorio que imprime o total livre e o maior pedaço livre contíguo. Aloque A = 300, B = 200 e C = 400, libere B, mostre o relatório e tente alocar D = 250. Depois libere C, mostre o relatório e tente D de novo.

Resposta
A em 0
B em 300
C em 500
livres: 300, maior pedaco contiguo: 200
D (250) em -1
livres: 700, maior pedaco contiguo: 700
D (250) em 300

Dica: no aloca, conte uma "corrida" de livres (zere ao achar uma posição ocupada); quando ela chegar a tam, o bloco começa em i - tam + 1. Há 300 bytes livres, mas em dois pedaços (200 onde era B e 100 no fim), e um bloco precisa ser contíguo: é a fragmentação externa. Liberando C, os pedaços se juntam num de 700.

6. Repetir texto. Escreva char *repetir(const char *s, int n) que devolve uma string nova com s repetida n vezes. Quantos bytes repetir("ab", 3) pede? E repetir("ab", 0)?

Resposta

"ababab" precisa de 2 * 3 + 1 = 7 bytes. Com n = 0, 1 byte só com o '\0': uma string vazia válida, que quem chama também precisa liberar. Monte com strcpy no primeiro e strcat nos seguintes, ou copiando com um índice.

7. O vetor que encolhe. Escreva um vetor dinâmico de int que começa com capacidade 1, dobra com realloc quando enche e corta pela metade quando a quantidade fica menor que um quarto da capacidade. Use int insere(int **v, int *qtd, int *cap, int x) e void remove_fim(int **v, int *qtd, int *cap). Insira 10, 20, ..., 90 e depois remova 6 vezes, imprimindo qtd e cap depois de cada operação.

Resposta
insere 10: qtd 1 cap 1
insere 20: qtd 2 cap 2
insere 30: qtd 3 cap 4
insere 40: qtd 4 cap 4
insere 50: qtd 5 cap 8
insere 60: qtd 6 cap 8
insere 70: qtd 7 cap 8
insere 80: qtd 8 cap 8
insere 90: qtd 9 cap 16
remove: qtd 8 cap 16
remove: qtd 7 cap 16
remove: qtd 6 cap 16
remove: qtd 5 cap 16
remove: qtd 4 cap 16
remove: qtd 3 cap 8

Dica: a função recebe int **v porque o realloc pode mudar o endereço do bloco; use um ponteiro temporário e só troque *v se ele não for NULL. No remove_fim, depois de (*qtd)--, teste *cap > 1 && *qtd < *cap / 4. O "um quarto" (e não "metade") evita o vai e vem: com metade, um insere e um remove alternados na fronteira fariam um realloc a cada operação.

8. Dois nomes, um bloco. Monte um programa com o trecho abaixo e rode com as flags de estudo:

int *a = malloc(3 * sizeof *a);
int *b = a;
b[0] = 5;
free(a);
a = NULL;
printf("%d\n", b == NULL);
printf("%d\n", b[0]);

Anote o que aparece. Depois conserte: guarde o valor de b[0] numa variável antes do free, zere os dois ponteiros e imprima guardado = ... e a == NULL: ..., b == NULL: ....

Resposta

A primeira versão mostra 0 e cai no b[0]: o compilador já avisa pointer 'b' used after 'free' e o ASan acusa ERROR: AddressSanitizer: heap-use-after-free. A consertada mostra:

guardado = 5
a == NULL: 1, b == NULL: 1

Dica: a = NULL muda só a variável a; b continua com o endereço do bloco liberado (um ponteiro solto). Zerar o ponteiro ajuda, mas não substitui saber quem é o dono do bloco.

9. O vazamento a conta-gotas. Escreva void tarefa(int chamada), que faz um malloc de 24 bytes, escreve um caractere no bloco e só dá free quando chamada é par; nas ímpares, soma 24 numa variável global vazou. Chame tarefa de 1 a 1000, imprima bytes sem free: ... e rode com as flags de estudo. Depois conserte a função e rode de novo.

Resposta
bytes sem free: 12000

==...==ERROR: LeakSanitizer: detected memory leaks

Direct leak of 12000 byte(s) in 500 object(s) allocated from:
    #0 ... in malloc ...
    #1 ... in tarefa ...

O seu contador e o LeakSanitizer batem: 500 chamadas ímpares × 24 = 12000 bytes em 500 blocos, com a linha do malloc apontada. Consertado (free sempre), sai só bytes sem free: 0, sem relatório. Dica: num servidor que roda essa função 1 milhão de vezes por dia, são 12 MB por dia.

10. Frase ao contrário. Use o dividir do E348 e uma função de juntar para inverter a ordem das palavras: "o rato roeu a roupa" vira "roupa a roeu rato o". A frase resultante deve ser um bloco novo, do tamanho exato.

Resposta

dividir com ' ' dá 5 pedaços. O tamanho final é a soma dos strlen (15) mais 4 espaços mais o '\0': 20 bytes, o mesmo tamanho da frase original. Monte percorrendo os pedaços do último para o primeiro. No fim, libere os 5 pedaços, o vetor deles e a frase nova.

Questões no estilo da prova

Formato da prova do mestrado do PPGI/UFAM. Resolva no papel, marque uma letra e só então abra o gabarito. Os trechos foram compilados com gcc -std=c17 -Wall -Wextra (e rodados com o AddressSanitizer nos casos de vazamento).

Questão 1. No programa abaixo, em que região da memória fica cada coisa: total, chamadas, n e o bloco apontado por v?

int total = 0;

void registra(int n) {
    static int chamadas = 0;
    int *v = malloc(n * sizeof *v);
    chamadas++;
    free(v);
}
  • (A) pilha, pilha, pilha, heap
  • (B) dados, pilha, pilha, heap
  • (C) dados, dados, pilha, heap
  • (D) heap, dados, pilha, heap
  • (E) dados, dados, heap, pilha
Gabarito

(C). Global e static moram nos dados (alocação estática) e duram o programa todo. Parâmetro e local moram na pilha (alocação automática). O bloco do malloc mora no heap (alocação dinâmica). A variável v está na pilha; o bloco para onde ela aponta, no heap. Veja 0053.

Questão 2. Sobre alocação dinâmica em C, considere as afirmações e marque a alternativa CORRETA.

  • I. calloc(n, tam) zera o bloco reservado, e malloc não.

  • II. Depois de free(p), o ponteiro p passa a valer NULL automaticamente.

  • III. Se realloc falha, ele devolve NULL e o bloco antigo continua válido.

  • IV. malloc pode devolver NULL, e o resultado deve ser conferido antes do uso.

  • (A) Apenas I e III

  • (B) Apenas I, III e IV

  • (C) Apenas II e III

  • (D) Apenas II e IV

  • (E) Apenas I, II e IV

Gabarito

(B). I é verdadeira: só o calloc inicializa com zeros. II é falsa: o free não altera p, que passa a apontar para memória devolvida (ponteiro pendurado). III e IV são verdadeiras. Por isso o realloc usa um ponteiro auxiliar: v = realloc(v, ...) perde o bloco antigo se falhar. Veja 0055.

Questão 3. v aponta para um bloco do malloc que precisa crescer para n inteiros. Qual forma é a correta?

  • (A) v = realloc(v, n);
  • (B) v = realloc(v, n * sizeof *v); if (v == NULL) return 1;
  • (C) free(v); v = realloc(v, n * sizeof *v);
  • (D) realloc(v, n * sizeof *v); e continuar usando v
  • (E) int *novo = realloc(v, n * sizeof *v); if (novo == NULL) { free(v); return 1; } v = novo;
Gabarito

(E). Se o realloc falha, devolve NULL e o bloco antigo continua vivo. Em (B), v = NULL apaga o único endereço dele: vazamento. (A) esquece o sizeof. (C) usa o ponteiro depois do free. (D) ignora que o bloco pode ter mudado de endereço. Veja 0055.

Questão 4. Rodado com o AddressSanitizer, o que o relatório de vazamento acusa ao final?

char *p = NULL;
for (int i = 0; i < 3; i++) {
    p = malloc(10);
    if (p == NULL) return 1;
}
free(p);
  • (A) nada: houve um free
  • (B) 30 bytes em 3 blocos
  • (C) 10 bytes em 1 bloco
  • (D) 20 bytes em 2 blocos
  • (E) double free
Gabarito

(D). Cada volta sobrescreve p com um endereço novo, e os dois blocos anteriores ficam sem ninguém que os aponte. O free final libera só o terceiro. O ASan mostra 20 byte(s) leaked in 2 allocation(s). Veja 0057.

Questão 5. Um vetor dinâmico começa com capacidade 1 e dobra a capacidade (com realloc) sempre que enche. Depois de inserir 100 elementos, quantos realloc foram feitos e qual é a capacidade final?

  • (A) 7 e 128
  • (B) 100 e 100
  • (C) 6 e 64
  • (D) 99 e 100
  • (E) 50 e 128
Gabarito

(A). A capacidade passa por 1, 2, 4, 8, 16, 32, 64, 128: sete dobras. As cópias somam 1 + 2 + ... + 64 = 127 < 2 · 100, então o custo total das inserções é O(n) e o custo amortizado de cada uma é O(1). Crescer de 1 em 1 faria 99 realloc e custo total O(n²). Veja 0055.

Questão 6. Uma matriz de 3 linhas e 4 colunas foi alocada como um bloco único: int *v = malloc(3 * 4 * sizeof *v);. Em que índice de v fica o elemento da linha 2, coluna 3 (contando de 0)?

  • (A) 9
  • (B) 14
  • (C) 11
  • (D) 6
  • (E) 12
Gabarito

(C). Linha após linha (row-major): i * colunas + j = 2 · 4 + 3 = 11. O 12 já está fora do bloco, que vai de 0 a 11. Veja 0056.

Questão 7. Uma matriz dinâmica de L linhas foi montada como vetor de ponteiros: int **m, com um malloc para o vetor de ponteiros e um para cada linha. Considere as afirmações e marque a alternativa CORRETA.

  • I. São L + 1 chamadas de malloc.

  • II. Para liberar, primeiro se libera cada m[i] e só depois m.

  • III. As linhas ficam garantidamente vizinhas na memória.

  • IV. Alocar tudo num bloco único, com malloc(L * C * sizeof *v), precisa de um só free.

  • (A) Apenas I e II

  • (B) Apenas II e III

  • (C) Apenas I e III

  • (D) Apenas III e IV

  • (E) Apenas I, II e IV

Gabarito

(E). I é verdadeira: uma chamada para o vetor de ponteiros e uma por linha. II é verdadeira: se m for liberado antes, os endereços das linhas se perdem e elas vazam. III é falsa: cada malloc pode cair num lugar diferente do heap. IV é verdadeira: é a variante de bloco único, indexada por i * C + j. Veja 0056.

Questão 8. Em uma plataforma de 64 bits típica (int de 4 bytes, ponteiro de 8), o que há de errado em int **m = malloc(3 * sizeof(int)); para guardar 3 linhas?

  • (A) Reserva 12 bytes, mas 3 ponteiros precisam de 24.
  • (B) Nada: int e int * têm o mesmo tamanho.
  • (C) Reserva 24 bytes, mas 3 ponteiros precisam de 12.
  • (D) Não compila: malloc devolve void *.
  • (E) Só dá errado se as linhas tiverem mais de 3 colunas.
Gabarito

(A). O vetor guarda int *, de 8 bytes. Com sizeof(int) o bloco tem metade do tamanho certo, e gravar m[1] já passa do fim. Escrever malloc(3 * sizeof *m) evita o erro. (D) é falsa: void * converte sozinho para qualquer ponteiro de dado. Veja 0056.

Questão 9. O que acontece com o programa abaixo?

int *cria(void) {
    int v[3] = {1, 2, 3};
    return v;
}

int main(void) {
    int *p = cria();
    printf("%d\n", p[0]);
    return 0;
}
  • (A) Imprime 1, porque o vetor foi inicializado.
  • (B) Não compila: função não pode devolver ponteiro.
  • (C) Imprime 1, porque o return copia o vetor para o main.
  • (D) Comportamento indefinido: v morre no return e p aponta para um frame que já não existe.
  • (E) Imprime 0, porque o frame é zerado no return.
Gabarito

(D). v mora no frame de cria, na pilha, e o frame some no return. O gcc avisa (function returns address of local variable) e, na prática, devolve NULL de propósito. O conserto é alocar com malloc (e o main dar free) ou receber o vetor como parâmetro. Veja 0053.
